# 升级到 v0.1.1

## 升级步骤

1. 在运行服务的终端按 Ctrl+C 停止服务，等待进程退出。
2. 备份正在使用的数据库。默认路径为 `data/agripulse.db`；如果使用了 `--db`，请备份该路径。若旁边仍有同名 `-wal`、`-shm` 文件，一起备份并保留原文件名。
3. 更新到 v0.1.1 代码，用原来的 `--db` 路径启动服务。
4. 检查两个模式下的阈值、设备列表及历史。自定义 API 客户端需按下文更新。

迁移在首次打开数据库时自动进行，使用同一事务，并设置 SQLite `user_version=1`；重复启动不会覆盖迁移后的配置。如果启动时报告迁移错误，请保留备份和原库，停止服务后检查错误，避免继续写入。

## 数据变化

- 增加 `devices` 注册表，从旧读数中恢复设备 ID、地块、来源、首次及最后上报时间。
- 旧阈值复制到 `device` 和 `simulator` 两个模式，初始数值相同，此后独立保存。
- 启动清理前先迁移设备，因此超过 30 天的最后读数被清理后，设备仍然存在。
- 设备绑定不因历史清理而解除。若需要调整地块，请暂时使用新的设备 ID；目前没有设备管理 API。
- 旧版已经删除的记录无法通过迁移恢复。

## API 客户端调整

`POST /api/threshold` 现在要求明确的来源：

```json
{"zone_id":"greenhouse-a","moisture_min":35,"source":"device"}
```

演示阈值使用 `"source":"simulator"`。缺少或无效的来源返回 HTTP 400，不会修改任何阈值。

`GET /api/summary` 的设备新增 `first_seen`、`last_seen`、`has_reading`。过期数据清理后，设备继续返回，但 `id`、`recorded_at` 及五个测量字段可能为 `null`。客户端应显示缺失状态，不能把它们当作零值；在线状态为 `false`。

遥测上报协议不变，仍由服务器分配接收时间与 `device` 来源。

## 回退

迁移后的数据库不支持旧版本。需要回退时，停止新版服务，单独保存升级后数据库及其旁路文件，再用完整的升级前备份和旧版代码恢复。不要把不同备份的数据库与 WAL 文件混用。回退到升级前备份不会包含升级后新增的读数。
